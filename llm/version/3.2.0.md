# 3.2.0

内蔵デバイス（インストゥルメント・エフェクト）の挿入を実機で使える状態にしたマイナーリリース。公開 MCP ツールは `meta` / `do` / `render` / `undo` の 4 つで変更なし。既存の読み書きは後方互換。

## 変更内容

### 内蔵デバイスの挿入

`CREATE (t)-[:HAS_DEVICE]->(d:Device {name, index?})` の実装は v3.0.0 から存在したが、Extensions SDK 1.0.0-beta.0 に `Track.insertDevice` が無く実機では動作しなかった。#145 で導入した 1.0.0-beta.1 が `Track.insertDevice(deviceName: string, index: number)` と `Chain.insertDevice` を公開したため、書き込み表面を実機で成立する形へ整えた。

- **Chain アンカー**: Rack のチェーン内へ挿入できるようにした。`MATCH (:Device)-[:HAS_CHAIN]->(ch:Chain) CREATE (ch)-[:HAS_DEVICE]->(d:Device {name, index?})`。LOM スキーマの関係に `HAS_DEVICE (Chain → Device)` を追加した（`LomGraphAdapter` は以前から Chain の `HAS_DEVICE` を展開していたが、スキーマ側に記載が無かった）。
- **挿入位置**: `index` 省略時はデバイスチェーンの末尾。指定時は `0` から既存デバイス数までの整数のみ受け付け、範囲外は `Device index N is out of range for this Track (valid: 0 to M)` を返す。暗黙に丸めない。
- **失敗時のエラー**: SDK の挿入が失敗した場合、内蔵デバイス名カタログとの照合結果を添えて返す。カタログ外の名前にはサードパーティ製プラグインを読み込めない旨を、カタログ内の名前にはエディション差や挿入先の不一致（オーディオトラックへのインストゥルメントなど）の可能性を示す。いずれも `validDeviceNames` にカタログ全体を含める。
- **preview**: `targets[]` に `insertInto`（`Track` / `Chain`）、`name`、解決後の `index`、`existingDeviceCount`、`inCatalog` を返す。
- **undo**: 挿入は `delete_created` の逆操作を記録し、`undoable: full` のまま。

カタログ（`apps/extension/src/tools/do/devices.ts`）は挿入の事前検証には使わない。SDK に Browser（デバイス列挙）API が無く手動管理のため、カタログ漏れした実在の内蔵デバイスを拒否してしまうことを避ける。

### スキーマ・ドキュメント

- `packages/lom-schema` の `relationships` に `HAS_DEVICE (Chain → Device)`、`create_patterns` に Chain アンカーの CREATE、例クエリに内蔵デバイス挿入を追加した。`meta` の応答へ反映される。
- 同じ関係型が複数の `from` ラベルを持つようになったため、`LomGraphAdapter` の関係型ヒントを重複除去した。
- `llm/models.yaml` に `packages/json`（3.1.2 で追加）の関数目録と、上記のスキーマ変更を記録した。
- `llm/device-catalog.md` にカタログを事前検証へ使わない理由を追記した。README に内蔵デバイス挿入の例を追加した。

## 動作確認

- `pnpm typecheck`: 7 タスク成功
- `pnpm test`: 4 タスク成功。`apps/extension` は 96 件（`built-in device insert` の 9 件を追加）
- `pnpm lint`: Biome 成功
- `pnpm build`: 成功

追加したテストが検証する範囲は次のとおり。

- 内蔵インストゥルメント（Wavetable）を MIDI トラックへ挿入する
- 内蔵エフェクト（Reverb）を `index:0` へ挿入し、既存デバイスの前に入る
- `index` 省略で末尾へ挿入する
- 範囲外の `index` が `out of range` のエラーになる
- 挿入失敗時に、カタログ外の名前ではサードパーティ製プラグインの旨、カタログ内の名前ではエディション差の旨を返し、`validDeviceNames` を添える
- `preview` が挿入先・名前・位置を返し、Set を変更しない
- Rack のチェーン内へ挿入する
- 挿入したデバイスを undo で取り除く

## 制約

- 実機（Live + Extension Host）での確認は未実施。テストはフェイク SDK による。実機での挿入可否・undo 挙動の確認は #107 で扱う。
- デバイス名は内蔵デバイスの表示名に一致する必要がある。SDK に列挙 API が無いため、名前の妥当性は挿入を試みるまで判定できない。
- サードパーティ製プラグインは SDK 上読み込めない。`.adv` / `.adg` のプリセット読み込みも Browser API が無いため対象外。
- 挿入されるのは既定プリセットのデバイスで、パラメータ値の指定はできない。挿入後に `HAS_PARAM` 経由で `SET p.value` する。
