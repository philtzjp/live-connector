# 3.2.1

`withinTransaction` の同期コールバック契約への逸脱を解消したパッチリリース。公開 MCP ツールと保存データ形式は変更なし。

## 変更内容

### 同期コールバックへの統一

Extensions SDK の `ExtensionContext.withinTransaction<T>(fn: () => T): T` は、型定義でコールバックが同期であること（内部で `await` しないこと）を要求している。`apps/extension` には `withinTransaction(async () => { const created = await create...(); created.name = ... })` の形が 13 箇所あり、`await` 以降の書き込みはトランザクションの外で実行されていた。次のファイルで同期コールバックへ統一した。

- `apps/extension/src/tools/do/create.ts`（MidiTrack / AudioTrack、Scene、CuePoint、アレンジメントの MidiClip / AudioClip）
- `apps/extension/src/tools/do/arrangement-edit.ts`（アレンジメントクリップの再作成）
- `apps/extension/src/undo/recreate.ts`（arrangement / session の MidiClip・AudioClip、CuePoint、Scene）

形は次のとおり。生成の発行を 1 トランザクションで行い、生成結果への属性設定をまとめて別の 1 トランザクションで行う。

```ts
const created = await deps.context.withinTransaction(() => track.createMidiClip(start, duration))
deps.context.withinTransaction(() => {
    created.notes = notes
    created.name = name
    created.color = color
})
```

従来は属性ごとの setter がそれぞれ自前のトランザクションを張っていたため、属性の数だけ undo ステップが増えていた。これを 1 ステップへまとめた。

### 契約の記録とテスト

- `llm/ARCHITECTURE.md` に「トランザクションと undo ステップ」の節を追加し、生成と属性設定を 1 undo ステップへ束ねられない理由を記録した。upstream への要望一覧へ「非同期コールバックを受け付けるトランザクション API」を追加した。
- `apps/extension/src/test-support/fake-transaction.ts` を追加した。SDK と同じ同期シグネチャを持ち、`async` 関数が渡された場合に失敗させる。`fake-live.ts` と `do.test.ts` のフェイクをこれに寄せた。
- 生成と命名が 2 トランザクションになること、名前を指定しない生成が 1 トランザクションで済むことをテストで固定した。

## 制約

- 生成と属性設定を 1 undo ステップへ束ねることは現行 SDK では不可能。SDK が示す回避策（`Promise.all([...])` を返す）は生成結果へ書き戻す用途に適用できない。Live の undo 履歴には「生成」と「属性設定」の 2 ステップが残る。
- MCP 側の undo ログ（`undo` ツール）は書き込み 1 件を 1 エントリとして扱うため、この分割の影響を受けない。
- 実機での undo 履歴の確認は未実施。#107 で扱う。
