# 3.1.0

AbletonOSC 連携と Main 出力の実時間録音（Hybrid 拡張）を追加したマイナーリリース。公開 MCP ツールは引き続き `meta` / `do` / `render` / `undo` の 4 つ。既存の `render`（AudioTrack Pre-FX）と `do` 読み書きは後方互換。

## 変更内容

### Hybrid Runtime

- activation 単位の singleton `HybridRuntime` を追加（`apps/extension/src/runtime/`）。OSC client・Transport / routing adapter・lock・resolver・capabilities を HTTP リクエスト単位で生成しない。
- OSC は `node:dgram` で送信 `127.0.0.1:11000` / 受信 `127.0.0.1:11001`（既定、loopback のみ）。未接続でも既存 SDK 機能は動作し、`meta` の `capabilities.render.mainOutput.available:false` と理由を返す。
- AbletonOSC は requestId を持たないため address 単位で直列化し、GET のみ限定再送、設定系は送信後に読み戻して確認する。読み戻し不一致は `OSC_WRITE_UNCERTAIN`。

### Main 出力の実時間録音（`render` の `source:"main"`）

- `preview` で実行計画（`planId`）を取得し、`planId` + `requestId` + `confirm:true` で実行。実時間再生のため常に background ジョブ（`background:false` は `REALTIME_REQUIRES_BACKGROUND`）。
- 一時 AudioTrack を SDK で作成し、OSC で Resampling 入力・Monitor Off・Arm・Sends Only を設定して録音する。一意名とトラック順序で SDK と OSC の接続先を照合し、不一致時は OSC 変更を送らない。
- Native Punch で録音区間を限定し、終了後に SDK の `renderPreFxAudio` でファイル化。`storageDirectory/renders/<jobId>/audio.<ext>` と `manifest.json` / `recovery.json` を残す。
- 終了時に loop / punch / record_mode / 停止位置を復旧し、一時トラックを削除（`keepCaptureTrack:true` なら消音・Disarm で保持）。競合は上書きせず `cleanupStatus:needs_attention` と `unrecovered` を返す。

### 限定 CALL と仮想ラベル

- `do` に `CALL transport.play()` / `transport.stop()` / `transport.seek(<beats>)` / `render.cancel(<jobId>)` を追加。許可手続きとリテラル引数のみ、`preview:true` は OSC 送信も含め副作用ゼロ、`confirm:true` 必須。`effect:"runtime"` / `undoable:"none"` で WriteEvent には記録しない。
- `Transport` 仮想ノード（読み取り専用、OSC 未接続は 0 行）を追加。`RenderJob` を `source` / `method` / `phase` / `progress` / `audioStatus` / `cleanupStatus` へ拡張。
- Main 録音中は書き込み・undo・別 render・`transport.play/seek` を拒否し、読み取り・job 照会・`render.cancel` は許可する。

### `render` annotations

- Main 録音が一時トラックと Transport を変更するため、`render` を保守的に `readOnlyHint:false` / `destructiveHint:true` / `idempotentHint:false` へ変更。

## 取り込み時のレビューで直した点

`Synohara/live-connector` の実装をレビューして書き起こす際に、次を変更した。いずれも回帰テストを添えている。

1. OSC 整数引数が int32 の範囲を超えると `writeInt32BE` が `ERR_OUT_OF_RANGE` を投げていた → 範囲外の整数は float32 として送る。
2. `OscClient.send()` が停止後も送信しようとし、閉じたソケットの生の例外を出していた → 未接続なら `OSC_UNAVAILABLE` を投げる。
3. artifact の上限判定がファイル全体を読み込む解析の後ろにあり、上限を超えたファイルも一度メモリへ載せていた → 判定を解析の前へ移す。
4. SHA-256 の計算でファイルを丸ごと 2 回目のバッファへ読み込んでいた → ストリームで計算する。
5. 確定されなかった `preview` の実行計画が module singleton へ溜まり続けていた → 計画の発行時に期限切れを捨てる。参照されていない `getRenderPlan` は削除した。
6. `keepCaptureTrack:true` でも OSC index を解決できなかった場合に一時トラックを削除しており、録音結果ごと失われ得た → 保持要求があるときは削除しない。
7. `CaptureJournal.argHash` が常に空文字列で、復旧記録から引数 hash が失われていた → 実際の hash を記録する。`CALL` の引数型不一致に 404 の `NotFoundError` を使っていた箇所を `BadRequestError` に改めた。

## 動作確認

本リポジトリには `ableton-sdk/`（上流提供の tarball、`.gitignore` 済み）が無く、`apps/extension` の `pnpm install` と `tsc` を実行できない。そのため検証は次の範囲で行った。

- `pnpm lint`: Biome 成功（変更後の全ファイル）
- `pnpm typecheck`: `packages/*` の 5 パッケージ成功。`apps/extension` は SDK の型定義が無いため未実行
- `pnpm test`: 175 件全緑（cypher 85 / lom-schema 8 / extension 82）。`@ableton-extensions/sdk` を既存の `src/test-support/fake-sdk.ts` へ解決する使い捨ての vitest 設定で実行した
- 上記 7 点の修正は、修正前のコードに対して対応するテストが失敗することを確認した

### 取り込み元での実機検証（2026-09-16、本リポジトリでは未再現）

以下は `Synohara/live-connector` が報告した結果であり、本リポジトリでは再現していない。環境: Ableton Live 12.4.15b2（macOS）/ AbletonOSC master（vendored pythonosc）/ Extensions SDK 1.0.0-beta.1 / 開発モード。実 Set（6 トラック・16 拍のアレンジ、テンポ 140）。

- `source:"main"` preview → planId → requestId + confirm で実行し、16 拍 @140bpm = 6.857 秒（302400 frames / 44100 Hz / pcm_s24le）の非無音 WAV を取得（RMS 約 -16.6 dBFS、peak 約 0.579）。
- Main の Utility を Mute した再取得は RMS 0 となり、`all samples are silent` の警告を返した。Main 上のデバイス処理が録音へ反映されることを確認。
- 終了後、一時トラックは削除され、loop / punch / record_mode / 停止位置が復旧した（`cleanupStatus:complete`）。
- AbletonOSC 停止時は `meta` が `osc.connected:false` と理由、`mainOutput.available:false` を返し、Main 実行は `OSC_UNAVAILABLE` で拒否された。

実機で検出され、本版に含まれる修正（いずれも同梱テストで再発防止）:

1. OSC ソケットが bind できただけで `connected:true` としていた → 起動時に `/live/song/get/tempo` へハンドシェイクして判定。
2. `back_to_arranger` は停止中 false を返すため Arrangement 可否を判定できない → Session clip の再生有無（`playing_slot_index`）で判定。
3. AbletonOSC setter の LOM 更新が非同期で、送信直後の 1 回読みでは反映前の値を観測 → 目標値へ収束するまで短期ポーリング。
4. SDK で作成・改名した一時トラックが OSC のトラック一覧へ現れる前に照合していた → 期限付きで反映待ち。
5. OSC index を解決できず失敗した場合に一時トラックが残った → SDK handle で自分のトラックを削除。

## 制約

- 本リポジトリでの実機検証は未実施。`meta` の `runtime.validationLevel` は既定 `unverified` のままとし、実験的機能として扱う（`LIVE_CONNECTOR_CAPTURE_VALIDATION_LEVEL=integration-tested` と検証 ID は利用者が設定する）。
- 取り込み元でも、Pre-FX レンダー（`select`）の実機確認、cancel・keepCaptureTrack の実機確認、複数 Set・テンポ変化・無人運用は未実施。
- 対応範囲は同一 PC・1 Live インスタンス・停止状態・Arrangement 再生。外部入力依存の演奏、外部クロック、任意のテンポ変化、無人運用、オフライン Main 書き出しは対象外。
- Ableton Extensions SDK v1.0.0 には Transport API がないため、Transport・録音・routing は OSC が担う。AbletonOSC の応答仕様（track 系 getter は `[index, value]`、設定反映は非同期）に依存する。
- Extensions SDK の tarball は beta.0 のまま据え置く。取り込み元は beta.1 へ上げているが、`ableton-sdk/` は本リポジトリに含まれない上流提供物であり、機能コードは beta.0 に存在する API しか使っていないため、beta.1 を持たない環境の `pnpm install` を壊す。
- `packages/env/.env.<scope>` は本リポジトリに未整備のため、環境変数は仕様既定値で動作する。

## インストール / 更新

- `pnpm package` で `apps/extension/dist/live-connector-3.1.0.ablx` を生成。Live の Preferences → Extensions から読み込む。
- Main 録音を使う場合は AbletonOSC を Remote Script として設定し、`LIVE_CONNECTOR_OSC_ENABLED=true` を設定する。OSC を使わない場合も従来機能は動作する。
- OSC server は既定で `0.0.0.0` に bind し得るため、loopback bind 設定または OS firewall で UDP 受信を制限する。
