# 3.2.2

Extension Host のプロセス終了を防ぐ保険を追加したパッチリリース。あわせて 3.2.1 以降に入った README の書き直し・CONTRIBUTING・CITATION.cff を含む。公開 MCP ツールと保存データ形式は変更なし。

## 変更内容

### Extension Host の終了を防ぐ保険

`apps/extension/src/runtime/crash-guard.ts` を追加し、`activate()` の先頭で `installCrashGuard()` を呼ぶ。`uncaughtException` と `unhandledRejection` を記録してプロセスを継続させる。

Extensions SDK は応答処理のコールバック内から `getObjectIsOfClass` を呼び、Live 側で対象を失った Handle に対して `TypeError: Invalid object reference` を投げる。これは非同期コールバックの内側で発生するため呼び出し側の `try/catch` では捕まえられず、Extension Host のプロセスごと終了させて同じホストに相乗りしている他の Extension も止めていた（#151）。

- 記録するのは `name` / `message` / `stack` と、SDK の無効な Handle に由来するかを示す `isInvalidObjectReference`
- `Error` 以外が投げられた場合も `NonError` として記録する
- `activate()` が再入してもハンドラは 1 組だけ残る（二重登録しない）

Node.js 一般の作法としては `uncaughtException` を握って継続するのは推奨されないが、Extension Host は複数の Extension を相乗りさせる共有プロセスであり、1 つの無効な Handle で全体を落とす方が失うものが大きいため、この文脈では封じ込めを選ぶ。

### ドキュメント

- `llm/ARCHITECTURE.md` の起動フローへ `installCrashGuard()` を追加し、封じ込めを選んだ理由と根本原因が SDK 側にあることを記録した。upstream への要望一覧へ「無効化された Handle の安全な扱い」を追加した
- `llm/models.yaml` に `crash-guard.ts` と `installCrashGuard` を記録した
- README のインストール手順を、Releases から `.ablx` をダウンロードする形へ更新した（3.2.1 までは Releases に配布物が無く `pnpm package` の実行を案内していた）

## 制約

- 本版は #151 の症状（プロセス終了）を止めるだけで、無効化された Handle が参照される原因は解消していない。原因は SDK 側の Handle キャッシュにあり、本リポジトリからは解消できない。該当の書き込みは失敗したままになる
- `uncaughtException` を封じ込めた後のプロセス状態が健全である保証はない。以降の応答が不正になる場合は Live の再起動が必要
- 実機（Live + Extension Host）での確認は未実施。#107 で扱う

## インストール / 更新

- Releases に添付した `live-connector-3.2.2.ablx` を Live の Preferences → Extensions から読み込み、Developer Mode を OFF にして Live を再起動する
- 3.0.0 からの更新でも移行手順は無い。保存データの形式は 3.0.0 以降変更していない
